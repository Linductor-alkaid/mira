# 阶段冻结与决策协议

> 状态：Active
> 版本：1.0
> 更新日期：2026-09-21
> 适用范围：里程碑内按阶段推进的工作（当前为 [M7](../plans/m7-tools-evaluation-platform-v1.md)
> 的 TR2 及后续阶段），以及任何"先冻结细项再进入实施"的计划节
> 上位决策：[DEC-043](../decisions/DEC-043-architecture-policy-and-baseline.md)

## 1. 目的

里程碑实践已经形成"每阶段进入实施前，在里程碑文件内冻结工作项与门禁"的节奏
（见 M7 准入条件）。本文把冻结时必须回答的问题、必须留下的记录模板和必须引用
的单一规则来源固定下来，使冻结文档在评审时可以逐项核对，也使后续阶段的实现
有稳定的决策上下文可读。

本协议只引用规则来源，不复制规则取值：

- 架构与依赖约束：[`tools/architecture-policy.json`](../../tools/architecture-policy.json)
  与[架构治理](architecture_governance.md)。
- 术语：[公共术语表](glossary.md)。
- 状态与勾选规则、验证证据等级：[项目管理与文档规范](project_management_and_documentation.md)。

## 2. 冻结时必答的八个问题

阶段冻结小节必须能对以下问题给出明确回答；答不出的问题要么补设计，要么显式
写为该阶段非目标。

| # | 问题 | 必须落到 |
| --- | --- | --- |
| 1 | 行为：本阶段改变或新增哪些行为？对应设计文档哪些冻结小节？ | 工作项引用设计节号 |
| 2 | 所有者：新增可变状态的唯一所有者是谁？谁只读投影？ | 工作项或设计引用 |
| 3 | 契约：最小公共契约面是什么（类型、schema、错误语义）？哪些调用方允许使用？ | 契约四件套清单 |
| 4 | 层与依赖：新文件属于哪个模块？include 方向是否已在 architecture-policy 登记？ | policy 差异说明 |
| 5 | 复用：哪条现有路径已承担部分职责？为何不新增平行路径？ | 工作项说明 |
| 6 | 时序：事件顺序、幂等键、过期结果规则、取消与 deadline 边界是什么？ | 门禁矩阵 |
| 7 | Executor 路由：每类工作由 Executor 哪种能力承载？句柄谁持有？关闭顺序如何？ | 设计或门禁引用 |
| 8 | 验证上下文：评审者最小需要读哪些契约、spec 与测试才能验收？ | 门禁矩阵列出测试文件 |

## 3. 决策记录模板

冻结小节末尾附一张决策记录表（写进里程碑文件，不必单独建文档；涉及第 8 节
文档规范中"必须决策"的变化时仍按规范建 `DEC-NNN`）：

```md
| 决策点 | 选择 | 被否备选 | 依据 |
| --- | --- | --- | --- |
| <状态所有者> | <组件> | <备选及否决原因> | <设计节或 DEC> |
| <命令路径> | <入口 → 所有者> | ... | ... |
| <派生视图> | <投影什么、从哪派生> | ... | ... |
| <时序/幂等> | <顺序、去重、stale 规则> | ... | ... |
| <Executor 路由> | <submit_auto/timer/realtime/worker> | ... | ... |
| <依赖登记> | <policy requires 差异> | ... | ... |
```

## 4. Golden 参照

冻结文档的形态以 [M7 §4.6 与 §5.6](../plans/m7-tools-evaluation-platform-v1.md)
（TR1 阶段：`M7-TR1-01`–`04` 工作项 + `M7-TR1-G1`–`G6` 门禁矩阵，跑前冻结、
同日交付取证）为参照：工作项引用设计文档冻结节号，门禁逐条可执行并指向
具体测试文件与标签。

## 5. 设计阶段应拒绝的形态

冻结评审中发现以下形状时退回，不允许带病进入实施：

- 为同一状态引入第二个写入路径、第二份队列或缓存。
- 绕过 Executor 的裸线程、私有定时器或 fire-and-forget 工作。
- 跨模块引用私有头（架构检查中的 `deep-import`），或未登记 `requires` 的
  新依赖（`module-dependency`）。
- 平台语义进入 Core，或 Adapter 承载规划/验证策略。
- 用超时掩盖同步问题；吞掉失败或无主异步任务。
- 原始模型文本未经解析校验直接驱动平台输入。

## 6. 冻结与解冻

- 冻结动作本身是一次文档变更：在里程碑文件内增补工作项、门禁矩阵与决策记录
  表，状态保持 `Planned`；实施开始后工作项转 `In Progress`。
- 门禁冻结后不得静默放宽；确需放宽时按项目管理规范第 5/8 节走决策或计划变更，
  并在验证记录中说明。
- 阶段关闭要求：全部工作项与门禁勾选、验证证据落档（commit、命令、结果）、
  受影响文档同步（设计、API 手册、术语表、总计划）。
