# DEC-119：M30 六类记忆的读写与索引边界

> 状态：Accepted
> 日期：2026-11-20
> 负责人：Mira Maintainers
> 冻结里程碑：M30
> 依据：维护者批准六类体系，承接 DEC-029、DEC-059、DEC-070 与 DEC-101

## 背景与问题

DEC-029 已将七种 MemoryKind 映射为四个检索域。M30 需要让人格、社交对象、环境
与目标具备各自的身份和权威来源，并给不同类别独立的候选额度。继续复用 EventStore、
MemoryConsolidator、IMemory、工作绑定和 Gateway 准入。

## 决策

以[六类记忆设计](../design/m30-memory-systems.md)冻结六类的权威来源、提交触发点、
检索键和失效语义。六类是生命周期和访问契约。DEC-029 的四域映射继续描述现有
MemoryKind，宿主配置、目标状态和注册表中的可执行资产由各自 owner 提交和读取。
向 Memory 保存的派生知识统一走既有校验与提交管线。

分类检索基于授权后的精确 scope、类别和结构化身份。单类查询独立消耗候选、
记录数和文本预算，结果按类别分别进入 Layer 0。语义相似度只给有余量且允许语义腿
的候选排序。类别不授予任何 scope。目标到期判定读取持久状态及时间索引。

首个增量在 MemoryAgentConfig 增加宿主显式配置的召回组，用已交付 MemoryKind
实现独立检索和配额。组按宿主顺序处理，Kind 在整个配置中唯一，单组和总量均受限。
每个查询文本共享现有存储检索软时限；软时限耗尽时报告部分结果，硬失败显式返回。
工作绑定、租户过滤、取消、撤权、删除和候选最终准入沿既有机制。空组配置沿用当前
召回行为。首个增量复用现有 SQLite 查询和索引格式，专用结构化索引随对应实体交付。

## 备选方案与影响

按六类复制数据库会使来源、权限和擦除演进出现多套实现。采用统一记忆管线和按类别的
检索配额，事实源依数据的所有权保持独立。新增公开配置字段需消费者重编译。配置多组
会增加存储查询次数，组数和一次工作内的查询数均有明确上限。真实数据下的索引规模、
排序质量和延迟按 M30/M31 后续验证。

## 验证方式

验证按类预过滤、各组配额、额外查询去重、当前授权、空结果、旧宿主兼容及入参拒绝。
人格权威、画像跨域、环境新鲜度、目标恢复及已撤回技能的验收见 M30 对应工作项。
