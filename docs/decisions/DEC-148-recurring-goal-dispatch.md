# DEC-148：重复目标触发的周期派发与提交回执

> 状态：Accepted
> 日期：2026-11-25
> 负责人：Mira Maintainers
> 冻结里程碑：M30
> 依据：[DEC-130](DEC-130-durable-recurring-goal-plans.md)、[DEC-132](DEC-132-calendar-goal-plans.md)、[DEC-145](DEC-145-durable-goal-dispatch-receipts.md)、[DEC-146](DEC-146-goal-dispatch-polling.md)

为当前计划版本的下一次到期触发保留稳定操作 ID。触发由归属、计划 ID、版本和预定时间
确定。准备只占用原有的触发额度，计划仍保留在同一到期位置。宿主按操作 ID 对账或去重
提交，使用常驻授权，并在准入时检查任务可执行性。收到确认后在同一 SQLite 事务保存
任务、会话和提交时间，推进仍处于该触发的计划。间隔计划和日历计划沿用各自既有算法。

结果未知时保留原操作 ID 和到期位置。替换或取消后旧触发不可再发起，已确认的历史提交
仍可登记，登记历史提交不推进新版本。擦除清理触发及派发回执。手动触发登记继续有效，
已被自动派发占用的触发由其提交回执推进。库版本升至 1.5，既有触发视为历史手动回执。

既有 Executor 派发器可同时检查一次性目标和重复计划。每种各读一页，两个游标独立，
共用检查时限并轮换先后，避免一类长期占用整轮检查。每个计划每页只处理一次触发，停机
积压沿预定顺序逐步补跑。提交回执只代表任务已准入。生产协调层的持久对账适配、兑现和
主动输出预算继续由 M30-37 与 M33 跟踪。

M30-45 验收 1.4 迁移、旧回执兼容、任务提交未知后的重开对账、分页补跑、额度、版本
变化、撤权、取消和擦除，以及一次性派发共存。详见 [M30 计划](../plans/m30-long-term-memory-integration.md#5-工作项)。
