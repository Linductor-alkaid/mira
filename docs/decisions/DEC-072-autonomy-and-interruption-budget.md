## 背景与问题

### 两个不同的缺口

Mirage 路线图 §4.6（Phase 5 自主行为）描述了一个完整但**从未向上游提报**的子系统；
而在它内部，还藏着一个**连 Mirage 自己都还没写出来**的缺口。

#### 缺口一：自主行为从未进入上游诉求

Mirage 已提报上游的唯一持续个体条目是 `MIRA-20261027-001`（= issue #111），
其来源范围在反馈计划中写死为路线图 **§4.2、§4.4～4.5、§5.2、§7.1**——
**§4.6 不在其中**。§4.6 是纯路线图文本，文档状态为 `Under Revision`，
并自述「本次核对未批准本文的公式、存储 schema、里程碑排期或新增记忆类型」。

§4.6 已有的自洽要素（本决策**沿用**，不重做设计）：

- 目标来源闭集 `GoalSource{UserExplicit, SelfGenerated, Scheduled, EnvironmentTrigger}`；
- 优先级闭集 `GoalPriority{Background, Normal, Urgent}`（本决策拆为
  `TaskOrigin` × `TaskPriority` 两个正交维度，见 DEC-071 §2）；
- 权限三分类：**允许**（只读）/ **需确认**（有副作用）/ **禁止**（高风险，
  无论用户是否在线）；
- 动机源四类：信息完整性 / 效率优化 / 社交维护 / 自我完善；
- 自主活动四原型：空闲记忆整理、主动提醒、后台学习、预测性准备；
- 用户控制：`autonomy.enabled`（默认 `false`）+ 四个分级开关
  `allow_background_only` / `allow_reminders` / `allow_learning` / `allow_predictive`；
- 反馈学习：称赞→加权、忽略→降频、中止→标记低价值、「不要再…」→永久禁用该类行为。

#### 缺口二：「什么时候说话」这一层在文档里**根本不存在**

这是本决策的**核心新增**。路线图全篇检索「勿扰 / 静默 / 冷却 / 打断预算 / 回复意愿」
**零命中**。现存最接近的四组参数全部属于**焦点切换**语义，**不是主动发言**语义：

| 参数 | 值 | 实际语义 | 是否覆盖「主动开口」 |
| --- | --- | --- | --- |
| `min_focus_duration` | 30s | 焦点最短驻留，防切换抖动 | ❌ |
| `urgency_threshold_for_interrupt` | 0.8 | 外部事件抢焦点的 urgency 阈值 | ❌ |
| 同类通知合并窗口 | 5s | 合并重复事件 | ❌ |
| 「勿扰模式」 | — | **用户锁定焦点**（focus lock） | ❌ |

「锁定焦点」与「用户正忙时不要弹出主动提醒」不是同一件事。
唯一的主动打扰闸门是 `Urgent` 优先级与「**需用户授权**」——
即：**授权**有规定，**意愿与频率**没有。

#### 缺口三：承诺与反馈计数没有承载实体

主动提醒的唯一触发源是「检测到用户承诺 + 接近 deadline」，
但 `AutonomousGoal` 只有 `earliest_start`/`deadline`，**没有** `promise_id` /
`fulfilled` / `reminder_count`。「用户忽略 → 降频」「3 次负反馈 → 永久禁用」
都需要计数承载物，**都不存在**。

#### 缺口四：自主行为的模块归属未表态

路线图 §4.6 写「Phase 5 作为**可独立启用的上层能力，不依赖 Mirage UI**」，
但全部类都写在 Mirage 的 `runtime/autonomy/` 路径下。
「Mira 提供一个 headless autonomy 层」还是「Mirage 私有实现 + Mira 提供底层能力」
——文档没有结论。这是上游必须表态的一条。

### 职责边界（依 issue #111 与 AGENTS.md）

- **Mira 提供**：确定性契约——自主行为的**接纳、预算记账、节流、优先级仲裁、
  审计、恢复语义、失败表达**。
- **宿主提供**：策略——**生成什么目标**、价值评估、是否该说话、
  `autonomy.*` 的 UI 与持久化、桌面租约与观察、权限确认 UI、
  「用户是否忽略了通知」的信号采集。

## 决策

### 1. 自主行为是**独立的第二输入源**，不是用户输入的变体

- **A1（两条通道分离）** 自主行为**不得**复用 `InputEnvelope`
  （[DEC-068 §3](DEC-068-interaction-coordinator-and-principal-input-entry.md)）。
  差异是结构性的：

| 维度 | 用户输入 | 自主行为 |
| --- | --- | --- |
| 授权主体 | `PrincipalContext`（已认证用户） | **无用户主体**；由宿主的授权配置界定 |
| 幂等键 | 宿主提供的 `input_id` | 自主目标自身的稳定标识 |
| 来源 | 用户发起 | `TaskOrigin::Autonomous` |
| 接纳判据 | 路由到哪个任务 | 是否**应当**执行（预算 + 权限 + 节流） |
| 优先级 | `UserInitiated` 恒优先 | `Autonomous` 不得越过用户任务（DEC-071 PR2） |

- **A2（共用下游纪律）** 但自主行为**必须**经**同一套**协调层纪律**：
  同一预算体系、同一租约纪律、同一条注意力竞争队列、同一事件审计面、
  同一恢复语义、同一失败表达。
  **不**允许自主行为成为绕过协调层的「后门执行路径」。
- **A3（不得绕过注意力）** 自主目标以与用户任务**同一评估队列**进入
  （[DEC-071](DEC-071-attention-focus-and-safe-switch.md) §4）：
  `Background` 只在焦点为空时执行；`Normal` 进入竞争；`High` 是抢占**候选**，
  仍受可中断性判定与授权约束。

### 2. 行为意图：`AutonomousIntent`（Core 侧可表达的闭集）

```cpp
enum class IntentSource : std::uint8_t {
    UserExplicit,       // 用户明确指示："每天提醒我"
    SelfGenerated,      // 宿主判定自主产生
    Scheduled,          // 定时触发
    EnvironmentTrigger  // 环境事件
};

struct AutonomousIntent final {
    std::string intent_id;              // 稳定标识 = 幂等键
    IntentSource source = IntentSource::SelfGenerated;
    TaskOrigin origin = TaskOrigin::Autonomous;
    TaskPriority priority = TaskPriority::Background;
    std::string goal;
    std::vector<std::string> required_capabilities;  // 所需能力（授权判定用）
    std::optional<Timestamp> earliest_start;
    std::optional<Timestamp> deadline;
    std::optional<std::string> promise_id;   // 关联的承诺实体（DEC-070 §4）
    double expected_value = 0.0;              // 宿主估计，Core 不解释
    double risk_level = 0.0;                  // 宿主估计，Core 不解释
};
```

- **I1（生成是策略，承载是契约）** Core 冻结上表的**字段与语义**；
  **生成什么目标、价值多少、风险多高由宿主决定**，Core 不解释这两项数值。
- **I2（承诺可关联）** `promise_id` 关联 DEC-070 §4 的承诺实体；
  到期检查**不得**依赖检索（P2）。
- **I3（不新增第二条任务路径）** 自主行为最终**仍是**一个 Task，
  经既有 `submit_task` 与同一 Task 状态机执行；
  **不**新建自主任务状态机、后台调度器或重试线程。
- **I4（意图不是动作）** 意图**不构成**执行授权；
  执行仍须过 §3 的权限判定与 §4 的预算判定。

### 3. 权限三分类：Core 侧同源判定

- **AU1（三分类闭集）** 自主行为按 **允许 / 需确认 / 禁止** 三类判定，
  与用户任务**同源**（同一 `PolicyEngine` 与 `ConfirmationAuthority`，
  [`include/mira/security.hpp`](../../include/mira/security.hpp)）。
- **AU2（需确认可挂起）** 「需确认」类**必须**有一个**可挂起等待用户授权**的中断点；
  等待期间任务**不推进**、lease **不持有**、预算**不消耗**。
- **AU3（禁止一律拒绝）** 「禁止」类**无论用户是否在线**都拒绝，
  且拒绝**不可被策略绕过**。
- **AU4（禁止清单不是产品配置）** 「禁止」类别由 **Core 的授权与安全策略**界定，
  **不**由宿主的 `autonomy.*` 开关放宽。宿主的开关**只能收紧**，**不能放宽**。

### 4. 打断预算：Mira 提供确定性机制，宿主提供意愿策略（核心新增）

本节冻结的是**机制**，不是**该不该说话**。Core 提供下列**确定性**闸门，
任何自主发言必须**全部**通过：

| 闸门 | 语义 | 归属 |
| --- | --- | --- |
| **类别开关** | 该行为类别是否被允许（提醒 / 后台学习 / 预测性准备 / 空闲整理） | 宿主配置，Core 强制执行 |
| **全局开关** | 自主能力总开关，默认**关闭** | 宿主配置，Core 强制执行 |
| **权限判定** | 允许 / 需确认 / 禁止（§3） | Core 判定 |
| **最小间隔** | 两次自主发言之间的最小间隔 | Core 强制，数值由宿主配置 |
| **合并窗口** | 窗口内的同类发言合并为一条 | Core 强制，数值由宿主配置 |
| **每类别频率上限** | 每类自主发言每天/每小时的次数上限 | Core 强制，数值由宿主配置 |
| **每日/每小时配额** | 自主任务数、模型调用数等 | Core 计数，数值由宿主配置 |
| **静默期** | 用户声明的不可打扰时间窗 | 宿主配置，Core 强制执行 |
| **冷却** | 被用户忽略或否决后的冷却期 | Core 计数 + 宿主配置 |

- **W1（确定性）** 上表每一项都是**可判定**的：给定（宿主配置、预算账本、
  行为历史、当前时间），Core 必须给出**唯一**的「允许 / 拒绝 / 合并 / 等待」结论
  与**理由**。**不得**由模型自由裁量是否打扰用户。
- **W2（静默期的例外是显式的）** 静默期**可以**被显式豁免，
  但豁免**必须**经授权路径且**必须**记录（与 AU3/AU4 同源）；
  「权限 / 接管 / 来源屏障」类事件**不得**被静默期静默。
- **W3（用户否决是强制不变量）** 用户说「不要再…」后，
  **该类行为必须被 Core 强制禁用**——不是「策略应当自觉」。
  Core 必须提供「按行为类别禁用」的持久状态，并在接纳阶段**拒绝**该类意图。
  这是本决策中**唯一**一条把宿主 UX 意图提升为 Core 不变量的规则。
- **W4（忽略是可观察事件，不是猜测）** 「用户忽略了发言」必须有**确定性信号**
  （如该发言未被消费、显式关闭、窗口被避让）。
  Core 只提供**计数与判定**，**不**推断用户心理；
  信号采集属宿主（表现层可见性）。
- **W5（反馈学习不构成授权）** 称赞/忽略/否决的计数**只影响频率与优先级**，
  **不得**提升权限分类（允许 / 需确认 / 禁止）。
  「频繁提到 ≠ 更可信」在行为侧同样成立（与 DEC-070 W3 一致）。
- **W6（频率上限不是全局的）** 每类自主行为的频率上限**独立**于全局配额；
  全局配额**不得**作为「没有分节流」的替代。

### 5. 预算的权威计数

- **B1（唯一计数 owner）** 自主行为的资源账本由 **Core 单一持有**，
  跨进程重启可靠。宿主**不得**另建一份计数。
  （若宿主只做内存计数，「每天 N 个」可被重启绕过。）
- **B2（日界与时区显式）** 「每日」配额必须声明**日界与时区**，
  不得依赖未声明的本地时区。窗口滚动与日历日的选择**必须**显式。
- **B3（预留—结算）** 沿 `BudgetLedger` 的预留—结算模式
  （[`include/mira/model_budget.hpp:79-113`](../../include/mira/model_budget.hpp#L79)）：
  执行前预留，执行后结算；未结算的预留**保留**，不当零消耗清掉。
- **B4（拒绝与豁免可审计）** 超预算的拒绝与优先级豁免**必须**产生可审计事件，
  豁免**必须**带理由。
- **B5（预算有版本）** 自主行为预算的冻结稿**必须**带 `budget_version`，
  与既有输入预算的冻结范式一致，便于跨版本比较与回放。
- **B6（与存储容量预算是两套）** 自主行为的**执行预算**（模型调用数、任务数、
  时长）与 DEC-069 的**存储容量预算**是**不同的两套**；
  但两者的**状态实体**（承诺、提醒计数、反馈计数、禁用标记）**必须**
  计入 DEC-069 §2 的总量预算并受其保护集合约束。

### 6. 审计与可观测

- **O1（全部决策入事件面）** 动机产生、目标选择、预算消耗、拒绝、豁免、
  合并、冷却、否决与禁用，**全部**写入统一事件面，可按主体/时间/类型检索。
- **O2（与用户任务事件可区分）** 自主行为的事件与失败**必须**可与用户任务的
  事件与失败区分（宿主 UI 需要据此呈现不同的错误与状态）。
- **O3（不记录敏感内容）** 事件载荷**不得**含凭据或敏感正文；沿既有脱敏规则。

### 7. 恢复语义

- **V1（自主任务不自动恢复）** 进程重启后，**未完成的自主任务不得自动恢复**，
  需**重新评估**后再决定是否执行。
  这与用户任务的恢复策略**不同**，且是**有意的**：自主行为没有用户在场确认，
  自动恢复可能重复产生副作用或打扰。
- **V2（承诺可恢复）** 承诺实体**可以**恢复（它是状态，不是副作用）；
  恢复后按到期检查重新评估。
- **V3（无自建调度器）** 周期检查与到期检查必须经 Executor
  （`submit_delayed` 重装链，见 [DEC-069 §9](DEC-069-bounded-capacity-and-forgetting-lifecycle.md)）；
  **不得**新建私有定时器、重试线程或平行任务状态机。
- **V4（调度唯一 owner）** 同一主体下的自主调度**只有一个** owner；
  宿主不得另建周期调度器。

### 8. 主动输出面

- **Y1（主动发言不等于模型回复）** 主动发言**必须**有一个
  **不依赖「当前模型请求」**的输出面。
  现有气泡通道绑定单个模型请求（模型活动即显示、请求结束即清除），
  **无法**承载「无请求的主动发言」。
- **Y2（输出面归属协调层）** 该输出面由协调层暴露，
  承载「已收到 / 正在处理 / 等待某条件 / 已回答 / 完成或失败」阶段
  （与 DEC-068 §3 一致），
  **并保留归属**（关联到 `intent_id` / `promise_id`，不是某次用户输入）。
- **Y3（表现与发言分离）** 主动的**表现**（动画、声音、气泡）是宿主表现层，
  **单向**投影（不反向影响认知决策）；主动**发言**是本决策的输出面。
  两者**不是**同一通道。
- **Y4（Y1 的交付分阶段）** 主动输出面**不**要求 Core 产生语音或动画；
  Core 只提供**带归属的文本/结构化输出面**。

### 9. 模块归属表态（回答 Mirage 的未决问题）

- **MOD1（Core 提供机制层，不提供策略层）** Core 提供一个 **headless 可运行**的
  自主行为**机制层**：接纳、权限判定、预算记账、节流、优先级仲裁、审计、
  恢复语义、主动输出面。
- **MOD2（策略层归宿主）** 动机生成、价值评估、目标选择、「该不该说话」的策略、
  `autonomy.*` 的 UI 与持久化，**全部**归宿主。
- **MOD3（不依赖宿主 UI）** 机制层**不**依赖宿主 UI 才能运行
  （对应 Mirage 路线图「Phase 5 不依赖 Mirage UI」）：
  宿主可以只接事件与输出面，不提供 UI。
- **MOD4（不新建 autonomy 模块）** 实现落在 `core` 模块 roots 内，
  **不**新增架构模块（`tools/architecture-policy.json` 零差异）。

## 备选方案

- **把自主行为当作 `InputEnvelope` 的一种**：否决（A1）。授权主体、幂等键、
  来源与接纳判据都不同；混用会让「无用户在场」的行为获得用户授权路径。
- **让模型决定要不要打扰用户**：否决（W1）。打扰是**用户成本**，
  必须由确定性机制裁决。
- **把频率上限只做成全局配额**：否决（W6）。全局「每天 5 个」不能表达
  「提醒每天最多 1 次、后台学习不限」这类分节流。
- **把「不要再…」做成宿主的自律约定**：否决（W3）。这是必须由 Core 强制的不变量，
  否则换一个宿主实现就失效。
- **把「忽略」交给模型推断**：否决（W4）。忽略必须有确定性信号。
- **用反馈学习提升权限分类**：否决（W5）。反馈只能影响频率与优先级。
- **把自主任务当用户任务恢复**：否决（V1）。自主行为无用户在场确认。
- **在 Core 里实现动机系统**：否决（MOD1/MOD2）。动机与价值是策略。
- **自主行为另建调度器与任务状态机**：否决（I3/V3/V4）。AGENTS.md 禁止平行生命周期。
- **把主动发言塞进气泡通道**：否决（Y1）。气泡绑定模型请求。
- **由 Core 产生语音/动画**：否决（Y3/Y4）。表现是宿主层且单向。

## 影响与风险

- **新增公开契约面**：`AutonomousIntent`/`IntentSource`、自主行为接纳入口、
  权限三分类判定、打断预算闸门、预算账本、按类别禁用状态、主动输出面、
  自主事件族。
- **既有契约**：`TaskSpec` 追加 `origin`/`priority`（DEC-071 冻结，追加式）；
  **不**改 `SessionState`、`TaskState`、既有事件类型。
- **风险 A-1（自主行为成为绕过协调的后门）**：缓解：A2 要求共用全部下游纪律；
  I3 要求最终仍是普通 Task；`M33-G` 门禁断言自主任务与用户任务走同一条命令面。
- **风险 A-2（打扰预算被绕过）**：缓解：W1 要求所有闸门确定性判定；
  W3 把否决变成 Core 强制；M33 门禁逐闸门断言。
- **风险 A-3（预算计数与存储容量预算混淆）**：缓解：B6 明确两套预算；
  执行预算管「做多少事」，容量预算管「占多少空间」。
- **风险 A-4（静默期被误用于压制安全事件）**：缓解：W2 明确屏障类事件不可静默，
  豁免须经授权路径并记录。
- **风险 A-5（自主行为在用户不在场时造成副作用）**：缓解：AU2/AU3 的权限三分类
  + V1 的不自动恢复；需确认类在无用户可确认时**不得**自动放行。
- **本决策不涉及 Executor 能力边界**：自主调度经 Executor timer
  （与 DEC-069 §9 同一承载）；**不登记** Executor 反馈台账。

## 验证方式

由 [M33 计划](../plans/m33-autonomy-and-interruption-budget.md) 承载，
门禁矩阵 `M33-G1`–`M33-G9`：

- `M33-G1` 通道分离：自主意图**不**走用户输入路径；
  自主任务的执行经与用户任务**同一条** `submit_task` 命令面。
- `M33-G2` 权限三分类：允许 / 需确认 / 禁止各有可复现用例；
  禁止类在用户在线与离线时**均**被拒；需确认类可挂起等待授权且不消耗预算。
- `M33-G3` 打断预算：九道闸门逐个断言——类别开关、全局开关、最小间隔、
  合并窗口、每类别频率上限、配额、静默期、冷却、权限判定；
  每道拒绝都有**确定理由**。
- `M33-G4` 强制否决：用户否决后该类行为被**Core**拒绝；
  计数跨重启可靠；反馈**不**提升权限分类。
- `M33-G5` 预算计数：跨重启后计数不丢；日界与时区显式；
  预留—结算语义；拒绝与豁免可审计。
- `M33-G6` 不绕过注意力：自主目标进入同一评估队列；
  `Background` 只在焦点为空时执行；`High` 抢占仍受可中断性与授权约束。
- `M33-G7` 恢复语义：重启后未完成自主任务**不自动恢复**；
  承诺实体可恢复并重新评估。
- `M33-G8` 主动输出面：主动发言**不依赖**模型请求；
  带归属（`intent_id`/`promise_id`）；与用户任务事件可区分。
- `M33-G9` 架构门禁与契约四件套同步；无自建线程/定时器/调度器。

真实模型语义质量（价值评估准确率、动机质量）留待标注场景与真实模型评估轮；
M33 只声明管线行为指标（RULE-10）。
