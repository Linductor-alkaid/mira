# DEC-155：在 Runtime 发布成功终态前持久化验证事实

> 状态：Accepted
> 日期：2026-11-25
> 负责人：Mira Maintainers
> 冻结里程碑：M30
> 依据：[DEC-151](DEC-151-live-goal-completion-publication.md)、[DEC-154](DEC-154-durable-before-live-task-admission.md)

持久派发的宿主可同时绑定准入与完成记录器。既有 `CompleteTask` 命令沿用正常状态校验，在
发布无错误的成功终态前，为该任务写入已有的验证完成事件。已绑定的写入权限限定于原主体、
会话与操作，适用于已接纳任务的结果记录，有效期独立于派发扫描。Goal Store 的兑现权限
和证据校验仍由对账入口处理。旧提交入口保留既有行为。

第一次验证请求固定事实发生时间和命令序号。Runtime 释放记录锁，在既有串行命令中等待
有界的本地 `ProcessCrash` 确认。持久写入失败时返回结构化错误，重复提交完成请求将用
同一事实重试。在此期间新增操作、任务暂停、任务恢复和进入恢复态返回 `ExecutionUncertain`，
迟到的操作结果按 stale 处理。取消、Human Takeover 和关闭继续受理。接管期间延期写入，
会话恢复后可以确认原验证事实。已持久记录的事实保留其原发生
时间，即使 Runtime 之后被取消或关闭。任务快照记录最终生效命令的时间和序号，并携带
原验证事实，供既有发布入口幂等复用。

M30-52 验收完成态可见性、稳定重试、接管、取消和跨 Runtime 重启兑现。运行在验证事实
写入前丢失时，目标仍待确认。事后验证和可恢复执行继续由 M30-37 跟踪。
