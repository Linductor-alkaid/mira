# DEC-130：重复计划与持久触发标识

> 状态：Accepted
> 日期：2026-11-23
> 负责人：Mira Maintainers
> 冻结里程碑：M30
> 依据：[DEC-119](DEC-119-six-memory-systems.md)、[DEC-129](DEC-129-durable-goals-and-commitments.md)

## 决策

目标库保存固定 UTC 间隔的重复计划。计划按精确租户、用户和稳定计划 ID 归属，定义带
来源事件、首次触发时间与间隔。创建、换版与取消受稳定 ID、当前版本和来源约束。
换版从新定义的首次时间恢复；取消关闭尚未登记的触发。处理已登记的历史回执可幂等重试。

一次触发由计划 ID、计划版本和预定时间确定。宿主按归属和下一次到期时间分页查询，
显式登记当前到期项。SQLite 在同一事务保存回执并推进下次到期时间，每次只推进一项。
发生停机积压时，由宿主按页评估各次触发。旧版未登记的触发被拒绝。擦除清理定义、取消
证据和触发回执，保留计划 ID 屏障。计划数、每主体活跃计划数和回执总数分别受限。

使用已有 Executor StoreChannel，触发登记只记录计划进度。动作执行和当前授权由宿主在
M33 派发入口复核。日历和时区计划、提醒计数及一次性目标纠正继续由后续工作项跟踪。

自动派发的准备身份、提交回执以及由提交确认推进计划的语义见
[DEC-148](DEC-148-recurring-goal-dispatch.md)。

## 验收

验证 SQLite 迁移、停机积压、并发重复、事务回滚、重开、换版、取消、隔离与擦除。见 M30-25。
