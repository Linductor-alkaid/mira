# DEC-152：用持久派发身份区分首次提交与事后对账

> 状态：Accepted
> 日期：2026-11-25
> 负责人：Mira Maintainers
> 冻结里程碑：M30
> 依据：[DEC-145](DEC-145-durable-goal-dispatch-receipts.md)、[DEC-146](DEC-146-goal-dispatch-polling.md)、[DEC-148](DEC-148-recurring-goal-dispatch.md)、[DEC-072](DEC-072-autonomy-and-interruption-budget.md)

一次性目标和重复计划的准备事务返回本次是否首次插入稳定派发身份。在配置了只读提交
对账回调的通道上，只有完成首次插入的调用可以发起提交。存在准备身份而缺少提交回执时，
派发器用原操作 ID 对账。查得原任务时登记原回执，查不到时保留待对账状态并继续分页。
同一触发或目标的并发准备只产生一次首次提交资格。该规则沿用既有目标库和当前存储授权，
适用于重启前留下的准备记录，无需迁移。

对账回调只查询宿主的持久准入结果，不创建任务。准备之后、确认之前发生崩溃或超时，
即使进程未能确认是否发起任务，也保持可对账状态。宿主可使用已确认的任务回执补记，
此增量不自动清除不明准备身份。既有未配置对账回调的入口继续要求其提交回调按操作 ID
完成幂等对账。一个归属的生产提交者应统一采用同一回调契约。

周期扫描沿用当前到期索引的版本、取消和截止时间筛选。已经离开该集合的历史派发，宿主
可按保存的操作 ID 查证并显式登记已确认的旧回执。

M30-49 验收一次性和重复派发的首次提交、持久重开、对账延迟、资格并发互斥及后续目标
的分页推进。生产自主准入和宿主持久任务结果来源由 M30-37 跟踪。
协调层提供的宿主准入回执见 [DEC-153](DEC-153-durable-task-admission-receipts.md)。
