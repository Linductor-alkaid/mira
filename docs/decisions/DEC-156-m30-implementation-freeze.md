# DEC-156：冻结 M30 剩余实施细则

> 状态：Accepted
> 日期：2026-11-25
> 负责人：Mira Maintainers
> 冻结里程碑：M30
> 依据：[DEC-069](DEC-069-bounded-capacity-and-forgetting-lifecycle.md)、[DEC-070](DEC-070-long-term-memory-behavior-contract.md)、[DEC-119](DEC-119-six-memory-systems.md)

## 主体与承诺

沿用 `memory_user_scope`、`memory_session_scope` 与 `memory_application_scope` 的版本化
摘要及显式租户字段。Memory Agent 的工作绑定校验当前归属及允许写入的具体范围。
承诺使用 [DEC-129](DEC-129-durable-goals-and-commitments.md) 定义的宿主
`SqliteGoalStore`，按归属及稳定目标 ID 查询。未兑现承诺使用有上限的保护配额，
即使从普通记忆清扫中豁免也计入 M31 总容量。到期、兑现和取消由目标存储状态解释。

## 候选提出、记录与审计

在交互结算且输入已对账后，Memory Agent 消费精确会话和任务的持久事件页。其他已验证的
社交、环境和技能事件由六类设计指定的宿主入口触发。显式记忆意图由当前主体的协调入口
提出。普通候选经 `MemoryConsolidator`，类型化候选经各自的所有者校验后写入。
模型仅提交引用了本次输入证据的候选。报告区分生效、拒绝、待批准和超限，诊断只保留
可追溯的标识、计数或原因码。精确写入范围各用自己的水位，已有版本及出处校验仍然生效。
事件区间及稳定操作身份用于幂等，待批准、超限及仍需重试的页保留其待处理状态。

## 记忆意图

协调层接受结构化的记住、纠正和忘掉意图。自然语言解释只提出操作或目标，宿主用当前
主体和精确 scope 解析引用。多条匹配或范围不明确时要求澄清。记住进入现有候选管线，
需要批准的显式偏好复用 DEC-109。纠正绑定目标 ID 与预期版本，经既有 mutation 管线
提交新版本。忘掉按精确记录或范围交给对应的擦除 owner，回执说明作用范围、发起者、
擦除状态及适用的派生结果。重试沿原操作查证，归属拒绝不泄露候选和版本。物理删除和
空间回收遵守 DEC-069。记忆中的授权描述不能授权这些操作。

## 价值信号

在记录版本上区分经明确用户意图或已验证事实确认的 `importance`，以及实际装入并由
Gateway 接受的请求所带来的使用信号。使用标识绑定请求身份、精确范围和记录版本，
每个请求对同一记录版本最多计一次，重放可以幂等折叠。仅命中查询、候选未被装入和失败
的准入均不计为使用。信号与查询相关性、验证级别分别保存和消费，随源记录擦除或失效。
M31 按精确 scope、记录 ID 和版本读取可选的已确认重要性、实际使用次数和最近使用时间。
缺少可验证证据时保留未知值，读取投影沿用当前 scope 授权。M30 交付信号输入及投影，
M31 负责淘汰、保护、回收与价值评估。激活公式和
使用信号参与排序仍按 DEC-070 §6 另行评审。

## 同 scope 删除后的接纳

稳定 scope 继续代表同一访问域，存储 owner 持久保存旧世代屏障和已删除来源的阻断信息。
只有当前授权下的明确新用户输入能启动新世代。先确认擦除并持久记录新的世代与可验证
来源，再开放新世代写入。读取、审批、作业和派生物均绑定世代。重放不能只凭事件到达
时间或更高序号重新接纳旧证据，任何引用旧世代来源的输入仍受屏障约束。旧摘要、旧审批
和在途结果失效。旧存储缺少世代信息时按旧世代处理，已有擦除屏障继续拒绝。M31 只能在
验证相关源、索引与备份均无法回灌后回收阻断信息。

## 实现边界

新写入沿现有 Interaction、Context 与 Storage 边界。Memory Agent 的阻塞工作继续由现有
Executor worker 承载，SQLite 操作沿 StoreChannel，宿主关闭时停止提交并回收结果和句柄。
提交前复核来源、归属、版本、取消和期限。此决策冻结行为与所有权，具体新增 ABI/schema
随各工作项登记。关系列表和验收见 [M30 §4.1](../plans/m30-long-term-memory-integration.md#41-实施细则验收)。
