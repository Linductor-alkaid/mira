# DEC-160：从已归因消息提取有向社交关系

> 状态：Accepted
> 日期：2026-11-25
> 负责人：Mira Maintainers
> 冻结里程碑：M30
> 依据：[DEC-125](DEC-125-social-relationship-assertions.md)、[DEC-143](DEC-143-social-message-references.md)、[DEC-159](DEC-159-evidenced-social-attribute-recording.md)

在已授权发言索引完成后，宿主可提交关系候选，或使用允许的谓词词表运行一次提取并
提交。模型只接收当前消息文本和谓词词表，输出谓词、另一端的原文别名、证据摘录和
方向。一端由当前发言对象决定，另一端经同一社交环境的目录解析。摘录必须包含原文
别名并逐字出现在消息中。缺失、同名歧义和自环候选在报告中保留位置。每条消息最多
八条候选，同一证据中的重复有向关系键拒绝整批候选。

记录入口复核原始文本和来源摘要，随后与社交擦除串行。在提交前重新解析发言人与
候选别名，比较归属、解析结果及目录版本。对象变更、擦除、取消或过期使旧结果失效。
目录别名的更新与该提交串行。
已解析的断言走原 `MemoryConsolidator` 并保持 `Inferred` / `Unverified`。同一来源和
关系键沿既有不可变身份去重，其他来源可保留各自证据。报告包含按候选位置排列的
解析结果、未写入位置及已提交候选的合并处置。

继续复用已配对的 SQLite 目录、记忆库和 Executor StoreChannel。初次读取及模型推断
在写入锁外进行，锁内逐条检查取消与期限。已生效条目可按原证据重试。生产统一触发、
跨来源同人推断及以代词或前序引用为另一端的自动关系接纳留在 M30-03 / M30-36。
