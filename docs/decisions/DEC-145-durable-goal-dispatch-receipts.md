# DEC-145：一次性目标的持久派发身份与回执

> 状态：Accepted
> 日期：2026-11-24
> 负责人：Mira Maintainers
> 冻结里程碑：M30
> 依据：[DEC-072](DEC-072-autonomy-and-interruption-budget.md)、[DEC-129](DEC-129-durable-goals-and-commitments.md)、[DEC-133](DEC-133-goal-store-live-authorization.md)

运行端通过专用到期查询发现待派发的一次性任务和承诺。准备派发时，目标库在同一个
SQLite 事务核对待处理状态、修订、到期和过期条件，保留一个稳定操作 ID。在同版本上
重试得到原回执。执行通道使用此 ID 查询或去重派发，独立于用户输入的生命周期。

提交回执记录目标版本、任务、会话和提交时间，并与准备身份绑定。相同回执重放幂等，
冲突提交被拒绝。收到回执的目标退出待派发列表，仍可按未兑现承诺查询。取消、纠正
或到期窗口关闭后，目标停止出现在待派发列表；已有准备记录保留，以便核对已发生的
提交。存在上一版本准备记录时，纠正不能自动发出第二个派发身份。对象擦除清理回执，
原有擦除屏障阻止重建。一次性目标最多一份派发记录，SQLite 库迁移到 1.4。

准备不提交任务，也不代表兑现。实际提交仍通过 M30-37 的协调层接线，在部署常驻授权
内运行。M30-43 验收到期筛选、版本竞态、重启重放、冲突回执、授权及擦除。重复计划
继续使用各次触发身份，后续补齐派发接线。
