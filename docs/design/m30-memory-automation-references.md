## 实施顺序

1. 平台 Adapter 从消息信封提取稳定来源账号，记录消息后解析当前发言者。M30-35 提供
   账号路径和按账号读取精确属性字段。同名仍经环境内候选集合处理。M30-40 核对已
   持久化的来源事件，并将发言者和事件位置一同索引。
2. 对最近的已记录对话运行有界提取。M30-41 提供发言者、被引用的参与者及正文别名
   的独立归因和候选检索。M30-42 自动提出正文引用，校验引用原文、前序发言和来源。
   为跨来源账号的同一性判断保留证据来源和反证。验收覆盖同名不同人、同人不同名、
   引用和多人对话、两个账号先分别建档后的归并和纠正。身份判断与属性、关系候选使用
   同一证据链，召回时保留时态和来源。
3. 从已持久化的承诺和计划发现到期目标，使用稳定目标及触发标识提交任务并回填回执。
   常驻授权部署允许 Agent 自发提交既有承诺。M30-43 至 M30-45 接通一次性目标和重复
   计划的发现及持久回执。停机后仍可发现到期候选，执行结果未知时用原标识对账。
   M30-46 按一次性目标的派发回执读取真实任务终态证据并兑现，M30-47 自动核对已提交的
   待结算目标，M30-48 按需从当前 Runtime 发布成功完成证据。M30-49 区分首次提交与
   只读对账，共用原操作 ID。M30-50 可从协调层的持久任务准入回执补记派发，M30-51 可在
   Runtime 发布任务前确认该回执。重复触发、提醒和任务结算各自保留状态。
4. 通用提取沿已授权且持久化的事件水位消费，按六类生成候选并走各自写入入口。保留
   每页有界处理、失败回执和来源可查。M30-39 接入结算后的固定快照多页处理。线上验收
   覆盖没有记忆指令的正常对话、断点恢复、边界隔离和擦除后重放。
